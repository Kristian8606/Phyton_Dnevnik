# Дневник

Локално десктоп приложение с Python 3.11, Qt Quick и SQLite. Отвори `Стартирай.command` на macOS или стартирай `.venv/bin/python -m cash_ledger` от тази директория.

На екрана за вход има две връзки. **Администратор** отваря създаване на първия профил с име за вход, парола и четирицифрен код за нулиране. След създаването на администратора същата връзка отваря нулиране. **Юзър** отваря регистрация с име за вход, парола и код `0000`. Всички профили отварят общия локален дневник.

При забравена парола избери **Администратор**, въведи предварително зададения код и избери име и парола. Кодът остава валиден след нулиране. Профилите на юзърите и данните в дневника се запазват. Ако при обновяване вече има администратор без код, същата връзка предлага еднократна настройка с името и паролата на администратора.

При първо отваряне на нова база таблицата е празна. Запиши първото захранване в **„П.“**. Полетата под таблицата записват за текущия ден. Клик върху датата отваря календар. Дните със записани операции имат точка под датата. Името на активния профил е горе до „Настройки“. Стрелките до датата сменят деня. Сумите на екрана са в евро.

На macOS записите са в `~/Library/Application Support/Dnevnik/dnevnik.sqlite3`. Приложението работи без интернет. За отделна тестова база подай `--database /абсолютен/път/до/тест.sqlite3`.

## Корекции и архиви

За редакция кликни върху клетка от съществуващ запис. Отваря се операцията от конкретния блок. Корекциите се записват за датата на операцията, а касата се преизчислява и за следващите дни.

**Пренос от предния ден** е началното салдо на показания ден.

Табът **Печат** отваря с избрано **Днес**. За повече дни избери **От–до**, после натисни **Печат…**. В първия ред на таблицата са датата или периодът, касата, печалбата, откупът, залозите и лихвите. След тях са записаните операции от текущия период. При повече от една дата редовете имат колона **Дата**. След изпращане на таблицата за печат се отваря табът **Операции**.

**Ревизии** показва текущия период и историята. Юзърът може да отвори **Нов период**. Администраторът потвърждава с името си за вход и парола, а профилът на юзъра остава активен. Програмата създава резервно копие, добавя обобщението към историята и изчиства операциите от приключения период. Крайната каса става начална за новия период, включително за нови операции на същата дата. Възстановяване от архив също изисква паролата на администратора.

**Търси** (⌘F на macOS, Ctrl+F на Windows) намира договори, етикети и залози по номер или част от него във всички дати. Изборът на резултат отваря деня и откроява съответния блок.

**Стартирай тестови дни.command** (или `python -m cash_ledger --demo`) отваря отделна база с четири примерни дни. Тестовите записи се създават веднъж. Следващото отваряне запазва корекциите.

От **Настройки → Архив → Създай архив…** запази копие във файл. На Windows архивите по подразбиране са в **Архиви** до програмата, а на macOS в **Дневник – Архиви** до приложението. Ако там няма права за запис, копията се създават в **Архиви** до базата. Отвори избраната папка от **Настройки → Архив → Отвори папката с архивите**. **Възстанови от архив…** изисква потвърждение. След потвърждение програмата проверява архива и пази копие на текущата база в папката с данните преди замяната.

След всеки запис или корекция програмата създава пълно копие на базата в подпапка **Операции** на папката за архиви. Името на всеки файл съдържа името на базата, датата и часа. Копията могат да се възстановяват от меню **Архив**. При неуспешно архивиране записът остава в дневника, а програмата показва предупреждение.

## Настройка в ново копие

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m cash_ledger
```

На Windows използвай `py -3.11 -m venv .venv` и `.venv\Scripts\python.exe` вместо `.venv/bin/python`. Първата версия е проверена на macOS.

## Тестове

```sh
.venv/bin/python -m unittest discover -s tests
```

Тестовете използват временни SQLite файлове. Сред проверките са касата от примерния ден, историята, записването с Enter и предупреждението при повече от едно поле за грамаж.

## Инсталиране и обновяване

При първото отваряне след преименуването „Дневник“ копира съществуващата база в новата папка с данни. Затвори предишната версия преди обновяване. На Windows стандартният файл е в `%LOCALAPPDATA%\Dnevnik\dnevnik.sqlite3`. Инсталаторът обновява програмата в `%LOCALAPPDATA%\Programs\Dnevnik`. За пренасяне на записи между компютри използвай **Настройки → Архив**.

### Windows през ново GitHub хранилище

Свържи локалното хранилище с празно частно GitHub хранилище. Запиши версията в `cash_ledger/__init__.py`. За първата версия командите са:

```sh
git remote add origin <URL-на-новото-хранилище>
git push -u origin main
git tag v0.1.3
git push origin v0.1.3
```

В **Actions → Windows installer** изтегли артефакта `Dnevnik-windows-x64` и стартирай файла `.exe` в него. Процесът също може да бъде стартиран ръчно от **Run workflow**. За обновяване запиши промените, увеличи версията, качи новия Git таг и пусни новия инсталатор на работния компютър. SQLite файловете и генерираните пакети се пазят извън Git.

### Обновяване от „Настройки“ на Windows

За обновяване без вход хранилището трябва да е публично и да има публикуван Windows инсталатор в **Releases**. Инсталирай веднъж версия 0.1.8 или по-нова.

В „Дневник“ отвори **Настройки → Обновяване → Провери за обновяване**. Приложението изтегля пакета директно през HTTPS и сравнява SHA-256 с публикуваната стойност.

Когато инсталаторът е готов, запази въведените операции и натисни **Инсталирай обновяването → Обнови и отвори отново**. Преди да замени програмата, Windows инсталаторът създава **Преди обновяване.sqlite3** в папка **Архиви** до програмата. При всяко обновяване провереното копие заменя файла със същото име. Ако архивът не може да бъде създаден, инсталаторът спира. Инсталаторът показва напредъка и отваря приложението. Изборът на тема и SQLite базата се пазят в папката с данни.

След успешно сглобяване и проверки на Windows новите Git тагове публикуват проверения инсталатор и в **Releases** на хранилището.

### Самостоятелен пакет на компютъра за разработка

```sh
python -m pip install -r requirements-build.txt
python packaging/build_app.py
```

При macOS резултатът е `dist/Dnevnik.app`. При Windows резултатът е `dist/Dnevnik`, а `packaging/windows.iss` е проектът за Inno Setup. Пакетът се изгражда на целевата операционна система.
