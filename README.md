# Дневник

Локално десктоп приложение с Python 3.11, Qt Quick и SQLite. Отвори `Стартирай.command` на macOS или стартирай `.venv/bin/python -m cash_ledger` от тази директория.

При първо отваряне базата е празна. Запиши първото захранване в **„П.“**. Полетата под таблицата записват за текущия ден. Клик върху датата отваря календар с избор на ден, месец и година. Стрелките до датата сменят деня. Сумите на екрана са в евро.

На macOS записите са в `~/Library/Application Support/Dnevnik/dnevnik.sqlite3`. Приложението работи без интернет. За отделна тестова база подай `--database /абсолютен/път/до/тест.sqlite3`.

## Корекции и архиви

За редакция кликни върху клетка от съществуващ запис. Отваря се операцията от конкретния блок. Корекциите се записват за датата на операцията, а касата се преизчислява и за следващите дни.

**Пренос от предния ден** е началното салдо на показания ден. **Каса по дни** отваря преглед за последните седем дни и дава пряк достъп до всяка дата.

**Търси** (⌘F на macOS, Ctrl+F на Windows) намира договори, етикети и залози по номер или част от него във всички дати. Изборът на резултат отваря деня и откроява съответния блок.

**Стартирай тестови дни.command** (или `python -m cash_ledger --demo`) отваря отделна база с четири примерни дни. Тестовите записи се създават веднъж. Следващото отваряне запазва корекциите.

От **Архив → Създай архив…** запази копие във файл. **Възстанови от архив…** изисква потвърждение. След потвърждение програмата проверява архива и пази копие на текущата база в папката с данните преди замяната.

## Настройка в ново копие

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m cash_ledger
```

На Windows използвай `py -3.11 -m venv .venv` и `.venv\Scripts\python.exe` вместо `.venv/bin/python`. Първата версия е проверена на macOS.

## Тестове

```sh
.venv/bin/python -m unittest discover -s tests
```

Тестовете използват временни SQLite файлове. Сред проверките са касата от примерния ден, историята, записването с Enter и предупреждението при повече от едно поле за грамаж.

## Инсталиране и обновяване

При първото отваряне след преименуването „Дневник“ копира съществуващата база в новата папка с данни. Затвори предишната версия преди обновяване. На Windows стандартният файл е в `%LOCALAPPDATA%\Dnevnik\dnevnik.sqlite3`. Инсталаторът обновява програмата в `%LOCALAPPDATA%\Programs\Dnevnik`. За пренасяне на записи между компютри използвай менюто **Архив**.

### Windows през ново GitHub хранилище

Свържи локалното хранилище с празно частно GitHub хранилище. Запиши версията в `cash_ledger/__init__.py`. За първата версия командите са:

```sh
git remote add origin <URL-на-новото-хранилище>
git push -u origin main
git tag v0.1.3
git push origin v0.1.3
```

В **Actions → Windows installer** изтегли артефакта `Dnevnik-windows-x64` и стартирай файла `.exe` в него. Процесът също може да бъде стартиран ръчно от **Run workflow**. За обновяване запиши промените, увеличи версията, качи новия Git таг и пусни новия инсталатор на работния компютър. SQLite файловете и генерираните пакети се пазят извън Git.

### Обновяване от „Настройки“ на Windows

Инсталирай първата версия с бутона за обновяване от **Releases**. За достъп до частното хранилище инсталирай GitHub CLI веднъж.

```powershell
winget install --id GitHub.cli --exact --source winget
```

Отвори нов прозорец на PowerShell и влез с GitHub акаунта, който има достъп до проекта.

```powershell
gh auth login --hostname github.com --web
```

В „Дневник“ отвори **Настройки → Провери за обновяване**. Приложението изтегля новата версия и проверява файла. Запази въведените операции и избери **Инсталирай обновяването**. Изборът на тема и SQLite базата остават в папката с данни.

След успешно сглобяване и проверки на Windows новите Git тагове публикуват проверения инсталатор и в **Releases** на частното хранилище.

### Самостоятелен пакет на компютъра за разработка

```sh
python -m pip install -r requirements-build.txt
python packaging/build_app.py
```

При macOS резултатът е `dist/Dnevnik.app`. При Windows резултатът е `dist/Dnevnik`, а `packaging/windows.iss` е проектът за Inno Setup. Пакетът се изгражда на целевата операционна система.
